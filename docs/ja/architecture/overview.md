| パッケージ | 役割 | 設計 |
|---|---|---|
| `internal/core/settings` | 設定ファイル (TOML) を読み、アラーム設定、アラーム音のファイル、長さ、音量、前倒し時間 (`[calendar] lead_time`、既定値10分)、監視サービスへの定期通知の間隔 (`[monitor] interval`、既定値5分、12秒より長い) を確かめた値にする。起床時刻を決めるたびにファイルを読み直し、読めないときは最後に読めた設定を使う | なし |
| `internal/core/monitor` | 続いている失敗の種類を持ち、監視サービスに今の状態を通知する。失敗の種類の始まり (`Fail`) と終わり (`Clear`) は状態を変えるだけで、すぐに戻る。通知は `Run` が自分の goroutine から送る。新しい種類の失敗が始まると失敗を、最後の種類が終わると正常を送る。起動の直後と設定の間隔ごとに、今の状態 (失敗なら続いている種類を並べた一覧、なければ正常) を送る。通知どうしは12秒以上あけ、そのあいだの変化は12秒が過ぎたときに1回で送る。通知できないときは `monitor notify failed` を記録し、次の通知は予定どおり送る。通知の送り先はインターフェース `Notifier` で表す | なし |
| `internal/core/calendar` | 予定を、カレンダーの提供元に依存しない形 (`Event`: 開始、終日、辞退、空き時間) で表す。カレンダーのアダプターが実装するインターフェース `Source` を持つ | なし |
| `internal/alarm` | 日付、アラーム設定、予定、前倒し時間、決める時点の時刻から、その日の起床時刻か「起こさない日」かを決める。起床時刻は、最初の予定の開始から前倒し時間を引いた時刻とアラーム設定の早い方とする。終日、辞退、空き時間の予定、その日の3時より前に始まる予定、決める時点で開始から1時間以上過ぎた予定は使わない。15秒ごとに設定と予定を読み直して起床時刻を決め、決定には理由 (`alarm setting`、`first event`、`none`) を記録する。予定を渡されないときは、予定がないものとして決める。起床時刻から1分以内に、日付ごとに1回、音量を設定してアラーム音を鳴らし、決定と開始と終了を記録する。起床時刻が決まった時点で過去であっても、その日にまだ鳴らしていなければ鳴らす。ただし、起動した時点ですでに過去である起床時刻では鳴らさない | なし |
| `internal/platform/alsa` | ALSA のミキサーの音量を `amixer` で設定し、音声ファイルを `mpv` で ALSA に直接、決めた長さだけ繰り返し鳴らす | なし |
| `internal/platform/google` | Google の OAuth クライアント (種類「デスクトップ アプリ」) の JSON ファイルを、スコープ `calendar.events.readonly` だけの設定にする。`127.0.0.1` のループバックへのリダイレクトと PKCE (S256) でリフレッシュトークンを得る。`state` が合わないか、コードがないときはエラーで終わり、トークンを返さない | なし |
| `cmd/press-start` | 家のサーバーの値を環境変数から読み、設定、ALSA のプレーヤー、スケジューラーを組み立てて、`SIGTERM` か `SIGINT` まで動かす。起床時刻のタイムゾーンは必須の変数 `TZ` から `time.LoadLocation` で読む。タイムゾーンのデータはバイナリに入れる (`time/tzdata`)。記録は JSON の行で標準出力に書く。変数が足りないか、`TZ` のタイムゾーンを読めないか、設定を最初に読めないときは、1行を記録して終了コード1で終わる。サブコマンド `press-start auth -client <パス>` は、ブラウザのあるコンピューターで1回だけ動かし、同意の URL を標準エラー出力に、リフレッシュトークンを1回だけ標準出力に書く。トークンはどのファイルにも書かない | なし |
