| パッケージ | 役割 | 設計 |
|---|---|---|
| `internal/core/settings` | 設定ファイル (TOML) を読み、アラーム設定、アラーム音のファイル、長さ、音量、前倒し時間 (`[calendar] lead_time`、既定値10分)、カレンダーを読む間隔 (`[calendar] read_interval`、既定値15分)、読むカレンダーの ID の一覧 (`[calendar] calendars`、既定値は空) を確かめた値にする。起床時刻を決めるたびにファイルを読み直し、読めないときは最後に読めた設定を使う | なし |
| `internal/core/calendar` | 予定を、カレンダーの提供元に依存しない形 (`Event`: 開始、終日、辞退、空き時間) で表す。カレンダーのアダプターが実装するインターフェース `Source` を持つ。`Source` は、カレンダーの ID の一覧と期間を受け取り、一覧が空ならメインのカレンダーを読む。トークンが期限切れか取り消されたことを表すエラー `ErrTokenExpired` を持つ | なし |
| `internal/alarm` | 日付、アラーム設定、予定、前倒し時間、決める時点の時刻から、その日の起床時刻か「起こさない日」かを決める。起床時刻は、最初の予定の開始から前倒し時間を引いた時刻とアラーム設定の早い方とする。終日、辞退、空き時間の予定、その日の3時より前に始まる予定、決める時点で開始から1時間以上過ぎた予定は使わない。15秒ごとに設定と予定を読み直して起床時刻を決め、決定には理由 (`alarm setting`、`first event`、`none`) を記録する。予定を渡されないときは、予定がないものとして決める。起床時刻から1分以内に、日付ごとに1回、音量を設定してアラーム音を鳴らし、決定と開始と終了を記録する。起床時刻が決まった時点で過去であっても、その日にまだ鳴らしていなければ鳴らす。ただし、起動した時点ですでに過去である起床時刻では鳴らさない。`Poller` は、スケジューラーとは別の goroutine で、起動の直後と `read_interval` ごとに、起床時刻のタイムゾーンで今日と明日の予定を `Source` から読み、最後に読めた予定を持つ。スケジューラーは `Poller` が持つ予定を受け取るだけで、カレンダーの応答を待たない。読めなかったときは最後に読めた予定を残し、`calendar read failed` をエラーと一緒に記録し、トークンの期限切れも含めて通常の間隔だけ待つ。1回の読み込みが間隔より長くかかるときは打ち切る | なし |
| `internal/platform/alsa` | ALSA のミキサーの音量を `amixer` で設定し、音声ファイルを `mpv` で ALSA に直接、決めた長さだけ繰り返し鳴らす | なし |
| `internal/platform/google` | Google の OAuth クライアント (種類「デスクトップ アプリ」) の JSON ファイルを、スコープ `calendar.events.readonly` だけの設定にする。`127.0.0.1` のループバックへのリダイレクトと PKCE (S256) でリフレッシュトークンを得る。`state` が合わないか、コードがないときはエラーで終わり、トークンを返さない | なし |
| `cmd/press-start` | 家のサーバーの値を環境変数から読み、設定、ALSA のプレーヤー、スケジューラーを組み立てて、`SIGTERM` か `SIGINT` まで動かす。起床時刻のタイムゾーンは必須の変数 `TZ` から `time.LoadLocation` で読む。タイムゾーンのデータはバイナリに入れる (`time/tzdata`)。記録は JSON の行で標準出力に書く。変数が足りないか、`TZ` のタイムゾーンを読めないか、設定を最初に読めないときは、1行を記録して終了コード1で終わる。サブコマンド `press-start auth -client <パス>` は、ブラウザのあるコンピューターで1回だけ動かし、同意の URL を標準エラー出力に、リフレッシュトークンを1回だけ標準出力に書く。トークンはどのファイルにも書かない | なし |
